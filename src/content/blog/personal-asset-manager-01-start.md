자산관리를 꾸준히 해보고 싶었지만, 내 생활 방식에 맞는 도구를 찾는 일부터 쉽지 않았다. 여러 방법을 사용해본 끝에 원하는 정보만 직접 기록하고, 그 결과를 대시보드와 차트로 확인할 수 있는 개인 자산관리 웹앱을 만들어보기로 했다.

프로젝트 이름은 **Personal Asset Manager**다. 기존 서비스에 없던 특별한 기능을 만들려는 프로젝트라기보다, 내 자산관리 방식에 맞는 도구를 직접 만들고 실제로 사용하면서 다듬어보려는 프로젝트다.

## 자산관리를 해보려고 했지만

이전까지 자산관리를 꾸준히 하지는 못했다. 한 번은 가계부 Excel 파일을 내려받아 사용해봤다. 정해진 양식에 직접 기록할 수 있다는 점은 괜찮았지만 휴대폰에서는 입력하기 불편했고, 매번 PC를 켜서 작성하는 일도 번거로웠다. 계속 사용하기에는 접근성이 아쉬웠다.

금융정보를 자동으로 불러와 자산 현황을 보여주는 모바일 서비스도 사용해봤다. 자동으로 정리된 내용을 편하게 볼 수 있었지만, 개인적으로는 모든 금융정보가 한꺼번에 나타나는 방식보다 내가 관리하기로 한 정보만 직접 등록하고 확인하는 방식을 더 선호했다.

수기로 입력하는 재정·예산 가계부 형태의 앱도 사용해봤다. 원하는 내용을 직접 등록할 수 있다는 점은 내가 찾던 방향과 가까웠지만, 화면과 정보 구성이 내게는 충분히 직관적이지 않았다. 기존 서비스가 부족했다기보다 내가 선호하는 관리 방식과 차이가 있었다.

이 경험을 통해 수기 입력 자체보다 **입력한 내용을 어떻게 확인할 수 있는가**가 내게 더 중요하다는 점을 알게 됐다.

## 내가 원했던 자산관리 방식

원했던 흐름은 비교적 분명했다.

> 필요한 정보만 직접 입력하고, 결과는 대시보드와 차트로 한눈에 확인한다.

모든 금융정보를 자동으로 모으기보다 내가 관리하고 싶은 계좌와 자산을 선택해 등록하고 싶었다. 수기 입력은 받아들일 수 있었다. 대신 기록한 결과를 다시 살펴보는 화면은 직관적이어야 했다.

단순히 매일의 소비만 기록하기보다, 여러 계좌와 자산이 현재 어떻게 구성되어 있는지를 함께 확인하고 싶었다. 입력은 필요한 만큼 직접 하더라도 조회할 때는 전체 상태를 빠르게 이해할 수 있는 방식이 필요했다.

## 처음부터 보고 싶었던 화면

처음 떠올린 핵심 화면은 다음과 같았다.

- 총자산을 한눈에 확인하는 대시보드
- 계좌별 금액을 비교하는 화면
- 자산 구성을 보여주는 차트
- 주식을 보유하고 있다면 종목별 보유 구성을 보여주는 차트

숫자를 입력한 뒤 표만 다시 확인하는 것이 아니라, 내 자산이 어디에 얼마나 나뉘어 있는지 시각적으로 보고 싶었다. 어떤 정보를 입력할지 직접 선택하면서도 결과를 확인하는 과정은 간단하고 직관적인 웹앱이 최초의 목표였다.

## 그래서 직접 만들어보기로 했다

기존 서비스가 제공하는 방식에 나를 맞추는 대신, 내가 관리하고 싶은 것만 관리할 수 있는 개인용 서비스를 직접 만들어보기로 했다. 직접 만들면 실제로 사용하면서 불편한 부분을 바꾸고, 내게 필요한 기능을 하나씩 추가할 수 있다고 생각했다.

처음부터 완성된 요구사항을 모두 정해놓기보다 작은 버전으로 시작해 직접 사용하고, 자산관리 방식이 달라지면 서비스도 함께 다듬는 방향이었다. 한 번 만들고 끝내는 예제보다는 계속 사용하면서 개선할 수 있는 도구를 만들고 싶었다.

## 첫 Codex 프로젝트로 선택한 이유

ChatGPT Plus를 사용하고 있었지만 이전에는 주로 대화와 프롬프트 중심으로 활용했다. AI를 이용한 개발과 바이브코딩, Claude와 Codex 활용 사례를 접하면서 Codex도 실제 개발 도구로 사용해보고 싶었다.

첫 Codex 프로젝트를 단순한 예제로 시작하기보다 내가 실제로 필요로 하고, 만든 뒤에도 계속 사용할 수 있는 서비스로 시작하는 편이 좋다고 생각했다. 그래야 결과가 내게 정말 유용한지 직접 판단하고 개선할 수도 있었다.

그렇게 **Codex를 실전 프로젝트에 처음 적용해보려는 목표**와 **개인 자산관리 서비스를 만들려는 목표**를 하나로 합쳤다.

## 첫 프로젝트라 기반부터 신경 쓰기로 했다

첫 Codex 프로젝트인 데다 Git과 GitHub, Supabase 등 여러 요소를 함께 사용하게 될 프로젝트였다. 앞으로 금융정보를 다루게 되는 만큼 보안도 처음부터 중요하게 생각했다.

그래서 기능을 빠르게 늘리는 것만 목표로 삼지 않기로 했다. Git 작업 흐름과 개발 단계의 경계, 비밀정보 관리, 데이터 접근 권한, 테스트와 검증처럼 프로젝트를 안전하게 이어가기 위한 기반부터 신경 쓰기로 했다.

구체적으로 어떤 기준을 세우고 어떻게 적용했는지는 이후 개발기에서 실제 기록과 함께 정리할 생각이다.

## 첫 버전은 작게 시작하기로 했다

첫 버전은 한 사람이 사용하는 반응형 웹앱으로 작게 시작하기로 했다. 원하는 정보만 직접 입력하고, 그 결과를 대시보드와 차트로 확인하는 흐름에 먼저 집중하는 방향이었다.

금융정보 자동 연동을 처음부터 기본 기능으로 넣지는 않기로 했다. 내가 선택한 정보만 관리하려는 방식에 맞고, 첫 구현의 복잡도를 낮춘 상태에서 핵심 경험부터 확인하기 위해서였다.

자동 연동을 영구적으로 배제한 것은 아니다. 일부 금융정보 연동이나 결제 후 기록 여부를 묻는 알림, 앱 형태로의 확장 같은 가능성도 장기적으로 열어두되, 실제로 사용하면서 필요성이 분명해질 때 검토할 생각이다.

## 이제 만들어보기로 했다

우선 내가 실제로 사용할 수 있는 작은 웹앱부터 시작하고, 직접 사용하면서 필요한 기능을 하나씩 추가해보려 한다.

이 블로그에는 완성된 결과만 보여주기보다 프로젝트를 진행하면서 어떤 선택을 했고, 어떤 문제를 만났으며, 어떻게 해결해갔는지를 실제 기록에 근거해 차례대로 남겨볼 생각이다.
